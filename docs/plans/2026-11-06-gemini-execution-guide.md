# 交给 Gemini 的执行安排

日期：2026-11-06。主计划见 [media-generation-plan](2026-11-06-media-generation-plan.md)。本文件是分轮任务说明，不代表任何阶段已经完成。执行者必须先读项目 `AGENTS.md` 与主计划，并以当前源码、Git 状态和硬件事实为准。

## 开始方式

建议一个阶段开一个新对话，首句只给对应任务包，附主计划路径；保留上一阶段的报告路径。每轮完成后先查看实际 diff、测试结果和真实产物，再决定是否进入下一轮。避免一次发出“完成 P0-P4”让模型跳过硬件验证。

当前工作区已有本文和主计划的改动时，实施者应保护它们；禁止为整理工作区而重置或覆盖不属于自己的修改。模型权重、引擎二进制、生成作品与长日志放在可追溯但不入 Git 的目录，不修改现有用户数据。

## 第 2 轮：P1 后端与独立图片服务

前提：P0 图片验证通过。任务提示：

```text
只执行主计划 P1，采用 P0 已验证的固定引擎/模型组合。实现独立媒体目录、已知模型导入、模型包校验、图片 runner、生成任务状态与作品登记；GUI 与 HTTP 必须调用同一任务核心。本机独立媒体服务先实现 image 模式和异步提交、查询、取消、读取产物；video/both 模式可以定义契约但不得显示为可用。默认只监听 loopback，落实鉴权和文件边界；端口冲突和停止/重启状态可见。把 llama 与媒体的启动准入做成后端原子门禁，覆盖控制平面和自动启动。保留原聊天与 headless 行为；媒体任务运行时禁止不受支持的模式切换。写聚焦测试及真实端到端证据，按仓库全门禁运行。不要扩展任意未知模型支持或 LAN 暴露。
```

本轮验收：命令行无 GUI 启动图片服务，提交任务拿 ID、查询、取消、取回受控产物；GUI 和 HTTP 任务状态相同；并发请求不会让 llama 和媒体同时争抢同一受管资源；进程退出不确定时不错误放行。历史配置与下载回归通过。

