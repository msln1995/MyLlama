「模型管理」页的「我的模型」标签汇总本机所有可用模型，每个模型都可以单独配置推理参数。启动 API 服务时，应用按这些参数为每个模型生成 llama-server 预设。

## 模型列表

列表合并了两个来源，并用标签区分：

- **下载路径**：通过「下载模型」标签下载的模型；
- **外部路径**：通过「选择文件夹」导入的已有目录。

每个模型卡片显示名称、架构（如 `qwen2`）、量化等级（如 `Q4_K_M`）、体积和完整路径。列表只收录真正的 GGUF 模型：一个改了 `.gguf` 后缀却不是 GGUF 文件的普通文件（Git LFS 指针、下载失败留下的 HTML 错误页）会被跳过——llama-server 本来就打不开它，让它进列表只会连累整个服务起不来。支持多模态的模型带「多模态」标记（检测到同目录的 mmproj 文件）。同目录放了多个投影文件时，实际加载（也被内存体积计价）的是按名称排在最前的那一个，其余不占内存；投影文件的体积会一并计入模型设置页的内存预估和启动前的内存检查。模型文件有变动时点「刷新」重新扫描。

## 打开模型设置

点击模型卡片右侧的齿轮按钮，进入该模型的独立设置页。参数按「基础参数 / 推理 / 内存·加载 / 多 GPU / 长上下文 / 高级」六个标签组织，每项都带使用建议。

## 一键调优

设置页右上有「一键调优」按钮，不需要你理解任何参数：

1. 点一下，应用读取模型 GGUF 文件的真实指标（层数、注意力头结构、KV 缓存几何、训练上下文、MoE 专家规模），结合本机硬件快照（显卡显存、内存、CPU 核心数、实测内存带宽）计算一组最优参数；
2. 计算结果**实时填进表单**——每一项（GPU 层数、上下文大小、缓存类型、CPU 线程等）都直接更新，你可以在保存前逐项检查、手动微调；
3. 确认无误后点「保存」。

调优会按你在设置页选择的**推理显卡**规划显存：多卡机器上选了哪张卡，就按哪张卡的显存算。可选方案包括全部卸载到 GPU（最快）、MoE 模型的 cpu-moe（专家层留内存、其余上 GPU）、部分卸载（显存放不下的兜底）和纯 CPU（无显卡时），上下文长度也会在显存预算内尽量选大。Apple Silicon（macOS arm64）走 Metal 方案：统一内存让全部层驻留 GPU，上下文按内存预算选最大、但不越过 Metal 设备自己的常驻工作集上限（实测 24GB M2 报 18186 MiB；超出后加载并不报错，服务照样"加载成功"、健康检查通过，之后每个请求都只回 Compute error 直到重新加载模型），运行开销按 Metal 实测计价（μBatch 512 时 320 MiB，是 CPU 口径 1280 MiB 的四分之一：层与缓存都在 GPU 侧，CPU 计算图不再持有批缓冲），同一模型因此比按 CPU 口径计价时多拿档上下文；但这个口径只属于「一层都没留在 CPU 上」的加载：把 GPU 层数显式设为 0、或设成小于模型层数的数值，Mac 加载仍按 CPU 口径计价（实测每留一层在 CPU 上约多占 63 MiB 的运行开销）。Flash Attention 不写死、交给 llama-server 自动选择（实测不比强制开启慢）；大小核机型（Apple Silicon、安卓 SoC）的线程数上限为性能核数量；若你已把 KV 缓存 K、V 都设为 `q8_0`，调参会保留这组量化并按实测 0.53× 的 KV 定价上下文（省下的内存变成更大的窗口，而不是只变成余量）；Linux 上 AMD / Intel 显卡同样会选中 Vulkan 构建进行 GPU 加速。

调优只改写它自己算出来的项：GPU 层数、上下文大小、CPU 线程、Flash Attention、KV 缓存类型、cpu-moe、μBatch 大小。你在设置页手动选的其余项都会原样保留——Batch 大小、加载方式、切分方式与每卡比例、主 GPU、RoPE 外推方式、视觉投影文件（mmproj）、Reasoning 推理输出、投机解码——再点一次「一键调优」不会把投机解码这类选择悄悄清掉。μBatch 是按你已有的值计价的：激活内存随它线性增长（实测 M2 同一模型 512→2048 多占约 1.6 GB），所以为了 prefill 把它调大，换来的是更小一档的上下文。

上下文快照同样由应用决定，不需要你设置。带滑窗注意力的模型在处理提示词时，会把「窗口那么大一份 KV」暂存若干份驻在内存里，应用把这个预算上限压在 8 份，而不是 llama-server 默认的 32 份——实测 M2 + gemma-3-1b Q4_K_M、上下文 16384：32 份时峰值内存 1.21 GiB，8 份时 1.09 GiB，而回看一条分叉过的提示词一样快（2.24 秒对 2.26 秒）。这份暂存会一并计入调优选出的上下文档位、模型设置页的内存预估和启动前的内存检查，不会出现某一页说「放得下」、守卫却拒绝启动。安卓方案和 Windows 全量卸载方案把这份预算设为 0：对这两类加载它换不来任何好处（聊天页只会往后追加对话，实测关掉快照速度一模一样、还省了 188 MiB 内存），却要和加载本身要用的内存抢。纯注意力模型没有滑窗可存，因此一分不计。

## 常用参数速查

| 参数 | 含义与建议 |
| --- | --- |
| GPU 层数 | `auto` 全部放进显存（推荐）；显存偏小时填数字做部分卸载；纯 CPU 推理选 `0` |
| 上下文大小 | 模型一次能"看到"的文本量；对话越长设越大，受显存限制 |
| CPU 线程 | `-1` 自动；CPU 较弱或发热明显时调低。大小核机型（Apple Silicon、安卓 SoC）自动调参只取性能核，实测 M2 4P+4E 纯 CPU 4 线程 21.5 t/s、8 线程 10.0 t/s；安卓上即使没有调参，`-1` 也直接按性能核数下发（见下方注） |
| Flash Attention | 勾选强制开启，不勾交由 llama-server 自动选择；实测 M2 Metal 解码 自动 30.0 ≈ 强制开 29.7，关闭 27.2 t/s |
| cpu-moe | MoE 模型（DeepSeek、Qwen3-MoE 等）显存不足时，把专家层留在内存 |
| KV 缓存类型 | `q8_0` 实测为 f16 缓存体积的 0.53×（几乎减半），代价是实测 M2 Metal 解码略慢（28.4 vs f16 30.1 t/s）。K、V 不同型时按两者的平均计价（`q8_0` / f16 实测 0.77×）。内存预估和启动前的内存检查用同一张表给每种类型计价，数字都是在 M2 上量到的实际内存台阶：f32 2×、q5_1 0.38×、q5_0 0.34×、q4_1 0.31×、q4_0 / iq4_nl 0.28×（这些只量过体积，速度与质量没有测过）。K 和 V 都选 `q8_0` 才构成完整的量化对：这样「一键调参」会保留它，并按 0.53× 的 KV 定价上下文，省下的内存直接换成更大的窗口（实测 4B Q4_K_M + 24GB 机器按 Metal 口径计价：64K 档约需 11.6 GiB 可用内存，q8_0 下约 7.4 GiB）；默认 f16 |
| 加载方式 | 默认 mmap 加载最快；内存充裕可选 mlock 防换页 |
| 切分方式 | 单卡选 `none`；多卡默认 `layer` 稳定 |
| 投机解码 | 「高级」标签。`ngram-simple` / `ngram-mod` 为 n-gram 自投机：无需草稿模型、零额外显存；`draft-mtp` 为 MTP 投机预测，需模型支持；留空关闭。实测 M2 Metal 4B Q4_K_M：输出高度重复时 `ngram-mod` 约 2.8 倍（86-88 vs 基线 31 t/s），自然语言无收益，`ngram-simple` 两种场景都慢约 5% —— 建议只在写代码 / 模板化输出时开启 |

> 注：Android 为纯 CPU 构建，页面不显示 GPU 层数、Flash Attention、cpu-moe 等 GPU 专属参数；「加载方式」中的 `dio` 仅 Windows / Linux 提供。Android 会自动识别 SoC 型号（如骁龙 / 天玑，来自系统属性）；「一键调优」在安卓与 Apple Silicon 上线程数上限为性能核数量（big.LITTLE 小核、M 系列能效核不参与推理线程），且纯 CPU 方案的调优结果提示不再显示 GPU 层字段。安卓上即使不调参，未设置的线程数也会按性能核数量下发：实测 vivo X60（Exynos 1080，4×A55 + 4×A78）+ Qwen3-4B Q5_K_M，4 线程解码 3.5–3.9 t/s、同一次请求 97–103 秒完成，而 llama.cpp 默认的满 8 核只有 0.35 t/s、443 秒——小核被推理线程占满后，系统界面和内存回收一起挨饿。实际下发的数值会记在 API 页的服务日志里（`direct mode: threads -1 -> 4`）；只有一个性能核的机型不做此限制，保持 llama.cpp 自己的选择。「高级」页的「Reasoning 推理输出」开关在安卓同样生效，会下发 `--reasoning off`：思考内容和正文一样都要逐字解码，推理类模型把它关掉省下的就是那段时间。

## 服务运行中修改参数

参数预设是在**服务启动时**生成的。如果服务正在运行，保存后页面顶部会提示「服务运行中 · 保存的参数将在重启服务后生效」——到「API 路由」页重启服务即可应用新参数。
